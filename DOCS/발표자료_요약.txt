[페이지 1] 이상온도 관제시스템 소개
* 프로젝트 개요: 의약품 및 식품 콜드체인(저온 물류)의 온도 이탈을 방지하기 위한 실시간 원격 온도 관제 및 하드웨어 모니터링 시스템.
* 핵심 컨셉: 중간 중계 서버 없이 엣지 단말기(Pico 2 W)가 직접 무선 LTE-M망을 통해 보안 클라우드 DB(Supabase)로 온도 및 부팅 자가진단 데이터를 직송하는 무막힘 데이터 흐름.
* 주요 기능:
  - 2초 주기 비동기 대시보드 관제 및 임계 온도 상한값 초과 시 즉각적인 시각 알림(Red Siren).
  - 수집된 기기 로그를 분석하여 조치 가이드를 제안하는 오울리 AI 관제 도우미 탑재.
  - PC 내장 웹 렌더러를 호출하는 경량 데스크톱 전용 앱 제공.

[페이지 2] 사용된 기기와 센서들
* 메인 컨트롤러(MCU): Raspberry Pi Pico 2 W (RP2350 기반, 듀얼 코어 ARM Cortex-M33 저전력 MCU).
* 무선 통신 모뎀: Sierra Wireless HL7811 (NB-IoT 및 LTE-M 셀룰러 통신 모뎀, 하드웨어 TLS 암호화 가속 탑재).
* 온도 센서: NTC 서미스터 (NTC Thermistor, 정밀 온도 측정용).
* 전원 상태 감시: 공급 전압(VSYS)의 실시간 변동을 계측하는 내장 아날로그-디지털 컨버터(ADC).
* 로컬 디스플레이: I2C 1602 LCD 스크린 (부팅 단계, 실시간 측정 온도, 네트워크 신호 감도 CSQ 노출).

---

[페이지 3] 사용된 아키텍처
* 클라이언트 (Edge Device):
  - C++ 기반 펌웨어 (Pico SDK): 듀얼 코어 제어 및 하드웨어 인터럽트 관리.
  - FreeRTOS 선점형 실시간 커널: LCD 제어, ADC 계측, LTE 모뎀 통신, 터미널 디버깅 태스크를 완벽히 격리 연산하여 시스템 먹통(Hang) 방지.
* 서버 (Cloud & Web Server):
  - BaaS (Supabase): 실시간 적재 DB 및 구글 로그인 회원 관리.
  - Flask 웹 서버 (Python): DB 쿼리 연산, 실시간 로그 JSON API 서빙 및 관계 테이블 인메모리 O(1) 초고속 조인 엔진 구축.
* 네트워크 구성 (Data & Auth Flow):
  - 데이터 전송: 단말(Pico W) -> LTE-M 셀룰러망 -> Supabase REST RPC (HTTPS TLS 1.2 보안 통신) 다이렉트 전송 (중계 서버를 없애 통신비 절감 및 데이터 암호화 보증).
  - 관제 화면: PyWebView 데스크톱 뷰어 -> Flask 웹 서버 (Port 8080) -> Chart.js 실시간 시각화.

[페이지 4] 회로도 구성
* 센서 신호 설계: NTC 서미스터와 10kΩ 정밀 풀업 저항을 결합한 전압 분배 회로를 설계해 Pico 2 W의 아날로그 입력단(ADC 0 / GPIO 26)에 연결.
* 전원 측정 설계: 보드 자체 전원 레벨 계측을 위해 Pico 2 W 내부 VSYS 전압 모니터링 핀(ADC 3 / GPIO 29) 연동 회로 수립.
* 통신 회로 설계: 1.8V 전압 레벨 시프터(Level Shifter)를 적용하여 Pico 2 W의 UART 신호선(TX/RX)을 HL7811 모뎀의 물리 핀에 결합.
* 로컬 출력: I2C 통신 버스 라인(SDA/SCL)과 LCD 백라이트 제어 트랜지스터를 디스플레이 보드에 결합.

[페이지 5] Issues 및 해결
* 웹뷰 구글 OAuth 로그인 거부 우회:
  - 문제: 임베디드 웹뷰 내에서 구글 로그인 보안 정책으로 인해 Touch ID 패스키와 로그인이 차단됨.
  - 해결: 기본 웹 브라우저를 띄워 구글 로그인을 거친 후 로컬 Flask로 토큰을 회수하여 세션을 매핑하는 루프백 세션 핸드셰이크(Loopback Session Handshake) 기법 구현.
* 무선 칩 간섭에 의한 VSYS 전압 오보고 (6.6V 현상):
  - 문제: Pico 무선 칩 공유 핀의 내부 풀 현상으로 보드 공급 전압이 비정상적으로 높게 오측정됨.
  - 해결: 전압 ADC 리딩 직전 gpio_disable_pulls(29)를 명시 실행하여 실제 인입 전압인 4.9~5.0V 대를 복원.
* 뮤텍스(Mutex) 락 내 sleep_ms 호출에 의한 시스템 프리징:
  - 문제: UART 자원 잠금 도중 컨텍스트 스위칭이 발생해 시리얼 통신 데드락 발생.
  - 해결: 락 내부의 컨텍스트 스위칭을 배제하기 위해 컨텍스트 전환이 없는 busy-wait 함수 sleep_us(500)로 전면 교체.
* HTTP 204 No Content URC 파싱 무한 대기:
  - 문제: 수집 완료 후 204 코드 수신 시 sscanf 파싱 제한으로 루프가 갇힘.
  - 해결: strstr 함수 및 쉼표 파싱 기반의 모뎀 버퍼 문자열 직접 스캔 로직으로 전환.
* 세션 누적에 의한 모뎀 통신 차단 (CME ERROR 912):
  - 문제: 단말기 전원 온/오프가 잦을 때 HTTP 세션 잔량이 누적되어 모뎀 내부 리소스가 고갈됨.
  - 해결: 단말 부팅 시퀀스 최선두에 1~10번 HTTP 세션을 강제 일괄 정화(Force Purge)하는 명령어 주입.
* SSL 인증서 UART 전송 시 버퍼 오버런 및 TLS 실패:
  - 문제: 115,200bps 환경에서 긴 인증서 전문 전송 시 데이터 누락 발생.
  - 해결: 2ms 단위 정밀 페이싱(Pacing) 지연 전송 도입 및 Cipher Suite 비트맵 필터링으로 보안 통신 성공률 100% 달성.

[페이지 6] 시연화면
* 실시간 종합 대시보드: 전체 가동 중인 설비 대수, 정상 가동률(임계 온도 이내 비율) 시간대별 추이 그래프, 실시간 수집 데이터 로그 스트림 제공.
* 기기 상태 (부팅 로그): 각 단말기의 고유 IMEI별 피코 공급 전압, 칩 온도, 플래시/RAM 자가진단 건전성, 통신망 신호 상태 배지 표기.
* 온도 상태 (실시간 임계 대조): 각 기기별 맞춤 임계 상한선을 비교하여 안전할 경우 초록 LED, 이탈 시 적색 사이렌 경고.
* 기기별 온도 변화 상세 추이: 담당자 클릭 시 최근 50건의 온도 기록을 보여주는 Chart.js 꺾은선 차트가 전개되며, 그래프 내에 설정 상한 온도선(붉은 점선)을 표출하고 임계 초과 지점을 붉은 도트로 강조.
* 오울리 AI 챗봇: Supabase 로그 데이터를 스캔하여 실시간 수치 데이터와 연동된 지능형 조치 답변 출력.

[페이지 7] 프로토타입 이미지
* IoT 수집 단말기 실물:
  - Pico 2 W 메인보드 및 HL7811 모뎀, 온습도 센서가 소형 박스형 케이스 내부에 조밀하게 실장된 외관.
  - 디바이스 전면에서 현재 온도 수치와 LTE 연결 신호(CSQ), 데이터 전송 성공 여부를 출력하는 1602 LCD 화면.
* 통합 관리자 소프트웨어 (PyWebView):
  - 오울리(Owly) 캐릭터 브랜딩이 적용된 수려한 다크블루 글래스모피즘 테마의 데스크톱 프로그램 창 레이아웃.
  - 상단 4대 메트릭 상태 카드(기기 수, 하드웨어 점수, 통신 점수) 및 Chart.js 반응형 차트 컴포넌트 시각 배치.
