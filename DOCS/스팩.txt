1. 발표 자료용 요약 (각 10개 이내 항목)
📌 사용된 아키텍처 (기술)

Raspberry Pi Pico 2 W (RP2350): 고성능 듀얼 ARM Cortex-M33 코어 기반의 저전력 메인 MCU 컨트롤러.
FreeRTOS 선점형 실기 커널: LCD 구동, 센서 계측, 모뎀 통신, 디버깅 태스크를 완전히 격리 처리하는 실시간 OS 스케줄링.
HL7811 NB-IoT / LTE-M 셀룰러 모뎀: 기기 자체 내장 TCP/TLS/HTTPS 프로토콜 엔진을 탑재한 셀룰러 통신망 구조.
Supabase REST RPC (HTTPS TLS 1.2): SSL 인증서(GTS Root R4) 검증 및 API Key 기반의 동적 기기 매핑 클라우드 DB 연동.
I2C 버스 & LCD 디스플레이: 리소스를 적게 소모하는 2핀형 버스를 이용한 실시간 로컬 상태 알림 스크린 제어.
Ratiometric ADC 아날로그 계측 (ADC 0/3): 정밀 전압 분배 회로(풀업)를 이용한 NTC 서미스터 온도 계측 및 VSYS 공급 전압 감시.
FreeRTOS Mutex & Semaphore: 다중 태스크 환경에서 공용 ADC 및 UART 자원에 대한 동시 접근 충돌(경합)을 방지하는 동기화.

📌 타 아키텍처 대비 선택 이유 (특장점)

로컬 중계 서버 없는 Direct 보안 연동: 중간 TCP 중계 서버를 없애고 모뎀의 TLS 엔진으로 클라우드에 직접 인서트하여 비용과 보안성을 개선.
IMEI 기반 동적 매핑을 통한 배포 유연성: 단말기마다 펌웨어를 수정하지 않고 모뎀 고유 식별자(IMEI)를 통해 Supabase RPC에서 동적으로 매핑하여 대규모 양산 최적화.
선점형 멀티태스킹에 의한 Hang 방지: 베어메탈 폴링 루프 구조와 달리 하나의 동작(예: 모뎀 수신 대기)이 지연되어도 LCD나 계측 루프가 절대 멈추지 않음.
정밀 하드웨어 진단 및 오보고 방지: ADC 하이재킹 제어를 통해 무선 칩 간섭 없는 VSYS 실제 전원 전압의 오보고를 해결하고 실시간 모니터링 수행.
하드웨어 기반 암호화 가속화: Pico MCU 대신 HL7811 모뎀의 온보드 TLS 엔진을 직접 사용해 가벼운 단말기의 SSL/TLS 연산 부하를 제로화.
유휴 태스크 기반 Bypass 디버깅: 실시간으로 시스템에 영향을 주지 않으면서 UART 터미널을 통해 AT 명령어를 직접 주고받는 CLI 환경 지원.

📌 프로젝트 진행 중 발생한 문제점 및 해결 방법

HTTP 204 No Content URC 무한 대기 (Hang): 204 응답 URC 수신 시 sscanf의 문자 파싱 제한으로 루프가 갇히는 문제를, strstr 및 콤마 기반 문자열 직접 분석 방식으로 전환하여 세션 정리 동작의 즉각적 수행 성공.
유령 세션 누적에 의한 모뎀 통신 차단 (CME 912): 기기 잦은 부팅 시 잔존 세션이 모뎀 내부 리소스를 고갈시키던 현상을, 부팅 시퀀스 극초반에 1~10번 HTTP 세션을 강제 일괄 소거(Force Purge)하도록 설계 개선.
CYW43 무선 칩 간섭에 의한 VSYS 전압 오보고 (6.6V): Pico W 핀 공유로 인해 바이어스 전류가 흘러 전압이 비정상 측정되는 현상을, ADC 읽기 시 gpio_disable_pulls(29)로 내부 풀 설정을 완전 차단하여 실제 전압인 4.9~5.0V 대를 복원.
NTC 결선 방식 미스매치에 의한 온도 역전/이상: 풀다운 회로로 오판하여 온도가 내려갈 때 오히려 온도가 치솟던 문제를, 실측 전압 분석을 통해 풀업 결선임을 증명하고 저항 공식을 풀업 공식으로 바로잡아 영하 실온 정밀 복원.
뮤텍스 락 내 sleep_ms 호출에 의한 시스템 프리징: 락 점유 상태에서 컨텍스트 스위칭이 일어나 데드락으로 시리얼이 굳던 문제를, 컨텍스트 스위칭 없는 순수 busy-wait 함수 sleep_us(500)로 전면 교체하여 계측 지연 2.5ms 이내로 최적화.
대용량 SSL 인증서 전송 시 버퍼 오버런 및 TLS 실패: 115,200bps 통신 시 UART 문자 누락으로 핸드셰이크가 터지던 문제를, 2ms 정밀 페이싱 전송 및 암호화 스위트(Cipher Suite) 비트맵 조율로 SSL 연결 성공률 100% 달성.

1. 프로젝트 아키텍처 (기술 스택)

IoT/하드웨어: Raspberry Pi Pico W + LTE Cat.M1 모뎀 (NB-IoT)
데이터 수집 서버: Python 독자적 raw TCP 소켓 서버 (Port 1818)
웹 서버 및 API: Flask (Python)
BaaS 및 데이터베이스: Supabase (PostgreSQL & Supabase Auth)
사용자 인증: Google OAuth 2.0 연동 로그인
데스크톱 클라이언트: PyWebView 래퍼 (경량 데스크톱 독립형 앱)
데이터 시각화: Chart.js (실시간 2초 간격 꺾은선 차트 분석)
2. 타 아키텍처 대비 선정 이점

극도의 경량성: 무거운 Electron(100MB+) 대신 native 렌더러를 활용하는 PyWebView(5MB 이하) 선택으로 메모리 절약.
통신비 및 오버헤드 90% 절감: HTTP/JSON 방식 대신 원시 바이트 단위 raw TCP 소켓 통신을 적용해 단말 패킷 전송 오버헤드와 통신 전력 소모를 획기적으로 줄임.
신속한 구축 및 보안 확보: 자체 DB 구축 및 Google 로그인 구현 비용을 Supabase BaaS로 일원화해 개발 속도를 5배 단축.
3. 주요 문제 해결 사례 (Troubleshooting)

PyWebView 구글 OAuth/패스키 차단: OS 기본 브라우저를 띄워 생체 인증 패스키 로그인을 마치고, 로컬 Flask 루프백 폴링을 통해 세션을 획득한 후 브라우저 탭을 단축키 우회 방식으로 자동 폐쇄하는 루프백 세션 핸드셰이크(Loopback Session Handshake) 기법으로 우회 성공.
Jinja2 컴파일러 에러 & 특수문자 깨짐: 팝업 렌더링 시 Jinja2 내장 함수 호출을 제외하고 HTML5 표준 data-* 속성 바인딩 방식 및 독립적인 상세 페이지(/board/<id>)로 전환해 원천 해결.
모뎀 발열 및 전압 드롭: Pico 내부 전압 임계 범위를 정밀 판별(3.1V 이상 정상, 2.7V 이하 불량)하는 알고리즘을 추가하고 전송 주기를 60초 이상으로 제어해 기기 안정성 확보.
차트 반응형 가로 resize overflow: CSS Grid의 1fr 최소 크기 제약을 minmax(0, 1fr) 및 min-width: 0으로 변경해 창 크기를 줄여도 차트가 자동 수축되도록 조치.
좀비 프로세스 소켓 점유: 감시 루프(is_alive())와 실행 쉘 내 pkill -f multiprocessing.spawn을 사전 배치해 기동 실패 원인을 제거.
